The H02 row is fully backed by tracked data — the menu item, the handler, and
three screenshot states that prove the on / off / on cycle.

## One open note (out of scope)

1. **The per-nation flag byte's meaning is not located.** The feature inventory's
   row prose notes that `TPremierForm_ToggleHints` "flips the application's
   `ShowHint`, the item's check and one per-nation flag byte (its meaning is not
   known)." This is **out of scope** for the H02 verification — the toggle's
   observed behaviour (the screenshot cycle) is captured; the meaning of the
   unknown byte is independent of the H02 row. Recorded only so it isn't lost:
   the byte is in the nation record and the decompile will be reopened when
   something reads it.

## Method

- **Form + function extraction.** Same toolchain as
  [`2026-10-08-help-topics-h01.md`](2026-10-08-help-topics-h01.md) and
  [`2026-10-08-cellular-automata-easter-egg-h04.md`](2026-10-08-cellular-automata-easter-egg-h04.md).
  `form_controls.tsv` holds the `mn_Showhints` row with `Checked=True`;
  `function_list.tsv` holds the named handler.
- **State-cycle evidence.** The three batch-2 screenshots record the on / off / on
  states; the **byte-identical hash** of `FI_b2_03_hint_on_before.png` and
  `FI_b2_03_hint_on_again.png` is the strongest single observation: a one-shot
  screenshot capture and a re-toggle + recapture produce the same pixels, modulo
  no race condition.

## Inferences

- The toggle's default value (`Checked=True` from the Delphi form resource) is
  also the runtime default — the saved form opens with hints ticked on. A clone's
  `ShowHints` analogue should follow the form resource's `Checked` rather than a
  hard-coded `True`.
