### F03 — Open

`mt_file/mn_Open` (form_controls row `PremierForm/MainMenu/mt_file/mn_Open`,
OnClick=`OpenGameFile`) opens the Windows file dialog. Coverage:
`coverage.md §1 'Open a save' ✅`. Help topic 3 ("Open") states *"Loads a
previously saved game."*. The research-side note
[`news-log-format-and-messages.md`](news-log-format-and-messages.md) Q5
'Loading a save re-announces the offer' records the side-effect of
re-loading.

### F04 — Save

`mt_file/mn_Save` (OnClick=`SaveGameFile`) routes to
`TPremierForm_SaveGameFile @ 0x0045ab84`. Help topic 4 ("Save") records
*"Back-ups are not made, if a file is re-saved with its name unchanged the
old file is over-written."*. The "no backup" behaviour is a path inside
`SaveGameFile` (a single `fopen` with `"wb"` mode, no `.bak`); not yet
decompiled cell-by-cell. **Carried as an open note** below. **Answered 2026-10-12** ([`2026-10-11-g1-original-checks.md`](2026-10-11-g1-original-checks.md)): the "overwrites silently" path exists only when a flag (`0x4a0334`), set by Open and by Save as, is set; after File > New with no Open or Save as in between, `SaveGameFile` calls Save as and opens the dialog with an empty name. Save after Open rewrote the opened file in place (one byte of 131,557 differs: the window height stored in the nation record).

### F05 — Save As

`mt_file/mn_SaveAs` (OnClick=`SaveGameFileAs`) routes to
`TPremierForm_SaveGameFileAs @ 0x0045abb0` (function_list.tsv; not cited
in the inventory row but present and one `OnClick` step after
`SaveGameFile`). Coverage: `coverage.md §1 'Save As' ✅`; test saves are
the canonical `T_*.SAV`. Help topic 5 ("Save as") describes the action.

### F06 — Close

`mt_file/mn_Exit` (form_controls row `PremierForm/MainMenu/mt_file/mn_Exit`,
caption `Close`, OnClick=`Quit`) routes to `TPremierForm_Quit @ 0x0045ac54`
(function_list.tsv). The yes/no prompt comes from the companion
`TPremierForm_CheckQuit @ 0x0045abec`, with the literal at
`dump_string_literals.v2.tsv` row 456: `"Are you sure you want to quit ?"`.
The `OnCloseQuery = CheckQuit` link is via `form PremierForm`
(`form_xrefs.tsv` reference; the `OnCloseQuery` property on the form's TPF0
record). Help topic 6 ("Close") cites the same wording. **Correction 2026-10-12** ([`2026-10-11-g1-original-checks.md`](2026-10-11-g1-original-checks.md)): `CheckQuit` asks only when some nation has the human flag (`FUN_00449050`), not always, and not depending on whether the game was modified; a window close (SC_CLOSE) gives the same box, and with no game loaded there is none.

## Three open notes

1. **F02's "names of computer nations are greyed"** is a runtime colour-
   state, not in TPF0. The `pnl_<nation>` rows carry no `Font.Color` setting
   in the extract; the runtime `OnMouseDown=HumanOrComputer` toggle on
   `cbx_<nation>` is what flips the grey. Reproducing the visual needs the
   form's runtime: on click of `cbx_<computer>`, set its
   `ed_<computer>.Font.Color := clGrayText` (or equivalent). **Recorded as a
   reproduction deliverable** for the clone's TPickLeaders analog, not as a
   missing verification.
2. **F04's "no backup"** is a single-`fopen` behaviour inside
   `SaveGameFile`; the function reads the save path, overwrites it, and
   returns. The path of *no* `.bak` rename and *no* "are you sure" is not
   in the literals table — would need capstone on `SaveGameFile`. (Read in the dump and played 2026-10-12: [`2026-10-11-g1-original-checks.md`](2026-10-11-g1-original-checks.md).)
3. **F02's "Several humans can be ticked"** is a multi-select state, not
   directly visible in the TPF0: each row's `cbx_<nation>` is independent,
   so up to 16 humans can be checked. The harness reproduced this with
   `T0_NEWGAME_AUTO0720.SAV` (humans 1 and 3). Carrying the multi-check live
   evidence is enough; a clone reproducing the F02 dialog just needs each
   checkbox to be independent + the OK handler reads them all.

## Inferences

- **F01/F03/F04/F05/F06 form a stack that routes all through one shape**:
  the menu item calls `OnClick`, the form's `OnClick` calls a named method
  in the same class, the method either asks for confirmation (`NewGame`,
  `CheckQuit`) or routes to file I/O (`OpenGameFile`, `SaveGameFile`,
  `SaveGameFileAs`). The shape is identical across the five rows; per-row
  verifications differ only by literal text (`Are you sure you want to ... ?`).
- **F02 is a fully separate form** (`TPickLeaders`) called from
  `TPremierForm_NewGame`'s Yes. It has 16 nation panels, each a self-contained
  sub-form (panel + checkbox + edit). The cleanest reproduction pattern is:
  16 panels under one form, OK walks the `cbx_<n>.Checked` to set the seat
  mask, then writes the leader-name string list. The TPF0 structure already
  encodes that nesting.

## What this does not establish

- F02's colour-state runtime for "computer names greyed" (above).
- F04's no-backup behaviour (above).
- The exact text of F03's file dialog when invoked (Delphi's standard
  `TOpenDialog`; not a custom form).
