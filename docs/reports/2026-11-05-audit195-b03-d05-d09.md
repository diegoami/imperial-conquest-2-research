## B03: mobilising next to an enemy army (DIFF, now level iv, hit in play)

- **The original:** the gap call's mobilise part runs `FUN_004504f4` → `FUN_0044a4e0` → `FUN_0044a120` / `FUN_00449f08` /
  `FUN_004492c0`. Nothing in it tests for an enemy army. A new army needs only a free tile with map code 2–11 in a 3×3
  area, and fewer than 198 army records (`DAT_004a0324 < 0xc6`).
- **The remake:** `AiEconomyPhase.ProposeMobilization` skips a slot whose city `IsThreatened`, a hostile army being
  adjacent (`AiEconomyPhase.cs:175`). Its own comment calls this the AI's designed restraint ("the original's
  FUN_004504f4 has no such test"). The Faithful economy reaches it through `AiFaithfulEconomy.cs:113`.
- **In play:** `thracia-rulebot1-40t`, Armenia at Erivan (city 297, (262,34)), with Seleucid's army adjacent at (263,33).
  - At t38 (7 ready slots, 41,500 men) and t39 (4 slots, 14,800), the original mobilises them, and Seleucid destroys the
    new army in each turn.
  - The remake mobilises nothing and loses no army.
- **The refusal:** a t38 replay with the AI log shows Armenia's economy at threat 67,717 against own 0, so the gap gate is
  open, and no mobilise follows. The army cap is excluded (28 records). The remake's `PlacementCell` was not probed. The
  original placed an army from the same state, so `IsThreatened` is the leading cause, not a proven one.
